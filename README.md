# ClassicDrop 1.6.2

Windows 与 macOS 下的 iPod classic 原厂曲库工具。面向已经有原厂曲库的 IPC3（2009 年末 160 GB 薄款）。所有日常操作都在本地完成。iPod nano 第 3、4 代使用同一种曲库，也可以读写，但还没有在真机上验证过，见「支持的机型」。支持 Windows 10/11 x64 与 macOS 12+（Apple 芯片和 Intel）；在 Windows 11 ARM64 电脑上以模拟方式运行 x64 版（Windows 10 ARM64 不能运行 x64 程序，不支持）。

## 安装与更新

从 [Releases](https://github.com/pretenderlu/ClassicDrop/releases) 下载 `ClassicDropSetup-v1.6.2.exe` 并运行。程序装在 `%LOCALAPPDATA%\Programs\ClassicDrop`，安装和卸载都不需要管理员权限。同一页面的 `ClassicDrop-Windows-x64.zip` 是免安装版，解压后运行其中的 ClassicDrop.exe。

启动后程序会向 GitHub 查询最新的正式版本。窗口右下角有 GitHub 链接、「反馈」和当前版本号。点「反馈」会打开一个小窗口，列出诊断信息（软件版本、Windows 版本、iPod 机型、最近一次报错和最近的运行日志）供先过目，再复制到剪贴板并打开 GitHub 的新建 Issue 页面。运行日志存在 `%LOCALAPPDATA%\ClassicDrop\Logs`，最多 3 个文件、每个 1 MB，会自动轮替。日志里会记录歌曲文件名；设备序列号、FireWire GUID 和设备名称一律不写入，写日志和诊断信息前会被替换成「[已隐藏]」，你的用户文件夹显示为 `~`。点版本号可以查看各个版本的更新记录。有新版本时，版本号旁边会出现一个红点，更新记录里会多出「下载并安装」按钮。点它之后程序下载安装包，核对 GitHub 提供的 SHA-256 校验值，再自动安装并重新打开。正在传歌，或待传列表里还有歌曲时，需要先处理完再更新。也可以随时点「工具与备份 → 检查更新」。下载失败时可以重试，或打开发布页手动下载。查询只访问 GitHub 的发布接口，不上传任何曲库或设备信息。

## macOS

[Releases](https://github.com/pretenderlu/ClassicDrop/releases) 页面上有两个 DMG：Apple 芯片（M 系列）选 `ClassicDrop-macOS-arm64-v*.dmg`，Intel 选 `ClassicDrop-macOS-x64-v*.dmg`。打开后把 ClassicDrop 拖进 Applications 文件夹。

程序没有经过 Apple 签名与公证。macOS 15 上第一次打开会被拦下：先尝试打开一次，再到「系统设置 → 隐私与安全性」里点「仍要打开」；也可以在终端执行 `xattr -dr com.apple.quarantine /Applications/ClassicDrop.app`。macOS 还可能在连接 iPod 时询问是否允许访问可移动宗卷，请允许。

程序位于可写文件夹（如「应用程序」）时，「下载并安装」会自动完成更新：下载对应机型的 DMG、校验 SHA-256、替换程序本体并重新打开；位于不可写位置或被移到隔离位置时，会打开 DMG 请你手动拖入替换。数据和日志在 `~/Library/Application Support/ClassicDrop` 和 `~/Library/Logs/ClassicDrop`。编码器直接使用系统内置的 afconvert（Apple 自己的 ALAC/AAC 编码器），不需要安装任何组件。Mac 格式（HFS+）的 iPod 只能在 Mac 上使用。macOS 版本还没有在真机上完整验证过，请先少量传歌确认。

## 支持的机型

| 机型 | 状态 |
|---|---|
| iPod classic | 在 2009 年末的 160 GB 薄款上实际使用 |
| iPod nano 第 3 代（2007 年，宽屏） | 可读写，尚未真机验证 |
| iPod nano 第 4 代（2008 年，竖长屏） | 可读写，尚未真机验证 |

nano 第 3、4 代的曲库格式和校验方式与 classic 相同。程序按机型写入各自的封面缩略图：nano 第 3 代与 classic 一样是四种，nano 第 4 代是六种。这些依据来自 iOpenPod 的机型资料，开发时没有这两款真机。连接后，设备卡片会标出「尚未真机验证」。

用 nano 测试时，第一次先传几首歌，弹出后在 iPod 上确认歌曲能看到、能播放、封面正常，再大量传入。每次改动前的曲库索引都会备份在电脑上，退回方法见「工具与备份」。最坏的情况下需要用 iTunes 恢复 iPod，这会清空机内的音乐。nano 能否播放 24 位的 ALAC 没有依据，不确定时在导入预览里选 AAC，或先试一首。

测试结果欢迎到 [Issues](https://github.com/pretenderlu/ClassicDrop/issues) 反馈。请写明机型和颜色、容量、固件版本，以及歌曲、歌单和封面在 iPod 上是否正常。

其他机型不在支持范围内。nano 第 1、2 代的曲库没有校验，程序会以只读方式打开，可以浏览和导出。nano 第 5 代及以后使用压缩曲库，程序会提示无法打开。

## 连接与传歌

1. 用可传数据的 30 针线连接 iPod，让 Windows 能看到设备盘符。关闭正在同步这台设备的软件。
2. 点「刷新」自动识别。也可以点「选择设备」打开含有隐藏目录 `iPod_Control` 的盘符根目录。
3. 点「导入文件夹」或「添加歌曲」，也可以把文件和文件夹一起拖进窗口。文件夹会包含子目录中的 MP3、M4A、FLAC、WAV、DSF 和 DFF。「导入预览」列出可读取的歌曲，点选一首即可查看封面与信息。
4. 核对或修改歌名、歌手、专辑、封面及传输格式。在「传入位置」选择已有歌单，或点旁边的「新建播放列表」输入名称。点「确认传入 iPod」，本批歌曲和新歌单会一起写入。设备已有的相同音频也会加入歌单。
5. 等传输完成后，点左侧设备栏的「弹出设备」。看到「已安全弹出」后拔线，在 iPod 的原厂「音乐」菜单中查找刚传入的歌曲或播放列表。Windows 提示设备被占用时，关闭占用它的程序或文件窗口，再点一次。只读连接也可以弹出，打开电脑上的曲库副本时按钮会禁用。

## 传输格式

- **Apple Lossless（ALAC）** 是 FLAC 或整数 PCM WAV 的默认选项。单声道或双声道音源在 24 位、48 kHz 以内（含上限）时，保留原采样率和全部音频采样。例如 16 位 / 44.1 kHz、24 位 / 44.1 kHz 和 24 位 / 48 kHz 均按各自的规格输出 M4A。
- **ALAC 24 位 / 48 kHz** 用于有效位深超过 24 位或采样率超过 48 kHz 的音源，包括高规格 M4A。超出任一项就固定转到此规格，例如 32 位 / 44.1 kHz、16 位 / 88.2 kHz 和 24 位 / 192 kHz。单声道保留，多声道混合为立体声。
- **DSF 和 DFF（DSD 音频）** 统一转换为 24 位 / 48 kHz PCM，再用 ALAC 保存为 M4A。DFF 支持未压缩的 DSD 和 DST 压缩，歌名和歌手会读取 ID3 标签或文件自带的 DIIN 信息。
- **ALAC 兼容转换** 可将位深和采样率在范围内的多声道 FLAC 或 WAV 混合为立体声。
- **AAC-LC** 适合节省机内空间，输出 M4A。目标码率为立体声 256 kbps、单声道 128 kbps，实际码率随音源而变化。
- **保留原文件格式** 默认用于 MP3 和 M4A（AAC-LC 或 ALAC），符合无损预设的 PCM WAV 也可以原样传入。原样传输支持单声道或双声道、最高 48 kHz。

转码器随软件提供（macOS 使用系统内置的 afconvert 作为 Apple 编码器）。FFmpeg 负责全部解码（FLAC、WAV、DSD、重采样和混音）。编码时优先使用 Apple 品质的编码器：ALAC 使用随软件提供的 refalac（启用 Apple 组件时为 qaac），AAC 在启用 Apple 组件时使用 qaac，其余情况用 FFmpeg 编码。启用方法是「工具与备份 → Apple 编码器」：程序会从 Apple 官网下载 iTunes 安装包（约 200 MB），校验 Apple 签名后只提取编码器需要的组件（约 43 MB）到 `%LOCALAPPDATA%\ClassicDrop\QTfiles64`，不安装 iTunes。电脑上装有从 Apple 官网下载的 iTunes 时，程序会自动使用其中的组件，不需要另外下载：第一次转码，或打开「Apple 编码器」菜单时检测（每次运行检测一次，软件运行期间新装的 iTunes 需要重启软件或打开该菜单后才会用上）。微软商店版 iTunes 的组件无法使用，需要通过菜单下载。如果菜单显示未启用，同样可以直接下载。同一菜单可以移除提取的组件。编码器失败会自动回退到 FFmpeg 并记入运行日志。确认传输后才开始准备音频，支持无 DRM 的本地文件。「保留原格式」保留音频编码。有标签或封面需要补全、修改时，程序在电脑上的临时副本写入这些信息，再将副本传入 iPod。源文件保留原样。

带内嵌封面的歌曲传入时，ClassicDrop 会为 iPod 原厂播放界面生成缩略图，并把封面关联到对应的歌曲。FLAC、WAV、DSF 或 DFF 内嵌的 JPEG、PNG 封面也会随转码保存在 M4A 中，有多张时优先使用标记为正面的图片。

如果旧版传入的歌在 iPod 上缺封面，连接设备后点「工具与备份 → 补齐设备封面」。程序从机内音频读取内嵌图，只更新原厂曲库索引和封面缩略图。状态栏会显示补齐数量和缺少可用图片的歌曲数。操作完成后即可安全弹出，在 iPod 上打开歌曲查看。

旧版中文 FLAC 的标签可能混用 UTF-8 和 GBK，ClassicDrop 会按字段解码。转码时如果缺少歌手，并且文件位于「歌手 / 年份-专辑」或其同名专辑子目录中，会用歌手文件夹补全。对于文件头时长与实际音频不符的 FLAC，程序会完整解码并校验转换前后的采样，再按实际时长写入。个别 FLAC 在音频末尾带有标签残留或无效字节，严格解码会报错：此时程序容忍性地完整解码一遍，核对采样数和文件自带的 MD5 校验值完全一致的按完好音频转换并记入日志；校验缺失或核对不上的按音频不完整拒绝传入，并给出检查提示。

也可以把音乐文件直接拖到 EXE 图标上加入待传列表。窗口内按 Ctrl+O 选择歌曲，Ctrl+Enter 传入，F5 刷新设备。

## 导入预览

歌名、歌手、专辑及封面优先使用文件内嵌信息，逐项补全缺失字段。文件缺歌名时使用文件名。缺歌手时先参考内嵌专辑歌手，再参考目录。支持「歌手/专辑」「歌手/年份-专辑」「歌手 - 专辑」，多碟专辑中的 CD1、Disc 2 等子目录会沿用专辑目录。推断的文字可在右侧直接改正。

封面优先选用内嵌正面图片。若缺失，会在歌曲目录、再在所属专辑目录识别 cover、folder、front、封面等常见图片名，也支持目录中唯一的候选图片。点「更换封面」可选择本地图片，点「移除封面」可取消本次导入的封面。确认后，所选封面会写入导入的音频和原厂封面库。

用 Ctrl 或 Shift 多选，也可点「全选」，一次修改多首的歌手、专辑、封面或格式。歌名逐首编辑。在同一个预览窗口可以追加文件或文件夹，也可以「移出本次」。取消会放弃这次预览中的修改。未连接可写设备时可先加入待传。

新建播放列表时，同一张专辑的歌曲会预填专辑名，可直接修改。选「加入待传」会在电脑上记住新歌单名称，连接设备后点「传入 iPod」才会创建。待传队列共用一个传入位置，可在传输前更换。直接从导入预览确认时，只传入该窗口列出的歌曲。

## 整理与导出

在「所有歌曲」中选中一首或多首，点「加入播放列表」选择已有歌单。左侧「新建播放列表」会以当前选中的机内歌曲创建普通歌单，未选歌曲时创建空列表。从待传队列新建的歌单会自动选为本批传输的目标。

点侧栏中的普通歌单即可上移、下移、移出曲目，或给歌单改名、删除歌单。Ctrl 或 Shift 可多选并整体移动。删除普通歌单只移除列表，歌曲仍在设备曲库和其他歌单中。智能歌单和系统管理的列表供浏览。

「所有歌曲」和歌单的右上方可以切换「全部 / 专辑 / 歌手」，程序会记住上次的选择，首次启动按专辑显示。三种方式的上方都以 Cover Flow 的样式排开专辑封面。选「全部」时下方列出所有歌曲，选中一首歌，封面带会滑到它的专辑，点一张封面则跳到这张专辑的第一首。选「专辑」时，左侧列出带封面的专辑，下方只显示正面那张专辑的曲目。曲目按音轨号排列，最前面一列显示音轨号，多碟专辑显示为「碟号-音轨号」。专辑名已经显示在封面带下方，这里的曲目表不再重复「专辑」一列。选「歌手」时，左侧列出歌手，点一位后封面带只排出这位歌手的专辑，点「全部歌手」排出所有专辑。点两侧的封面、滚动鼠标滚轮或按左右方向键可以换专辑，左侧列表会同步。封面取自 iPod 上已有的原厂缩略图，正面附近的封面会在空闲时读取更清晰的版本。在歌单中调整顺序时使用「全部」。

「工具与备份 → 主题」可在浅色和深色之间切换，立即生效。主题和浏览方式保存在 `%LOCALAPPDATA%\ClassicDrop\settings.json`。系统自带的菜单、提示框和文件选择窗口沿用 Windows 的外观。

在「所有歌曲」或歌单中可搜索歌名、歌手和专辑。曲目表的「评级」和「播放」两列显示每首歌的星级和播放次数，包括在 iPod 上打的星和上次同步后新增的播放。这些来自曲库和 iPod 自己的 `Play Counts` 记录。打星就像在 iPod 上一样：鼠标移到「评级」列会显出 5 个位置的空槽，点第几颗就是几星，点当前的星则清除。连点几首歌的评级会攒在一起，最后一次点击约 2 秒后一次写入；写入前状态栏会显示「有 N 首歌曲的评级待保存」，旁边的「撤销」可以全部取消。选中一首或多首歌，右键点「评级」也可以设为 1 到 5 星或清除。保存评级时，程序会像 iTunes 同步那样把 `Play Counts` 里的星级和播放次数合并进曲库，再移除这个文件，改动前的文件备份在电脑上。传歌和补齐封面时也会这样合并。删除歌曲和修改歌单不合并，会保留这个文件。右键或点「选中项操作」可以导出原始音频到电脑，双击一首歌可修改机内曲库的歌名、歌手和专辑。

修正以前传入的歌曲时，可多选同一位歌手的歌曲，右键点「批量修改歌手」并填写名字。此操作更新原厂曲库中的歌手，保留音频文件、播放次数和歌单关系。

移出歌单会保留机内歌曲。修改曲库信息对原始音频文件的内嵌标签没有写入操作。导出时保留原始音频、选择可读文件名，遇到同名但内容不同的文件会加序号。也可将一个已复制到电脑的 iPod 根目录作为打开参数，如 `ClassicDrop.exe "D:\iPod副本"`。

## 删除音乐和修改设备名称

选中一首或多首歌曲后，右键点「从 iPod 删除歌曲」，确认框会显示设备、歌曲数量和部分歌名。确认后从设备曲库及相关歌单移除歌曲，并释放机内对应音频的空间。用 iTunes 同步并开启过 Genius 的歌曲，删除时会同时从 iPod 的 Genius 数据（`Extras.itdb`）里移除，改动前的文件备份在电脑上。在「所有歌曲」中按 Delete 会打开此确认框。在普通歌单中按 Delete 仅将选中的条目移出歌单。

「工具与备份 → 清空音乐库」适用于整台设备，包括当前搜索或歌单以外的歌曲。核对设备和数量后，输入「清空」才会执行。普通歌单会保留，播客、有声书、视频、设置和用户文件也会保留。程序只清理原厂音乐目录中受曲库管理、且已无其他曲目引用的歌曲文件。需要保留的音频可先多选并「导出到电脑」。

「工具与备份 → 修改设备名称」可修改原厂曲库中的 iPod 名称，也可以按 F2 或双击侧栏设备名称。支持中文。Windows 资源管理器中的磁盘卷标由 Windows 单独管理。

## 工具与备份

「打开电脑上的曲库索引备份」会打开每次改动前保存的 `iTunesDB`。备份位于 `%LOCALAPPDATA%\ClassicDrop\Backups\设备GUID\旧库摘要\iTunesDB`。它可用于找回曲目记录、歌单或旧设备名称。已经删除的音频需要另存的音频副本才能还原。需要手动退回索引时，先退出软件并另存设备当前的索引，再把匹配此设备的备份复制回 `iPod_Control\iTunes\iTunesDB`。回到旧索引后，此后传入的文件仍在磁盘上，但会从旧索引中消失。

「恢复中断操作」用于写入过程中掉线或断电。把 iPod 重新接回操作时的电脑，点此项。传歌时会先写入并校验音频和本批封面，再提交曲库。更新封面前，程序会把已有的 `ArtworkDB` 备份到电脑上的同一目录。意外中断时，会按设备实际使用的曲库恢复本批封面。删除时会临时移走待删音频，保留其余歌曲的顺序，并更新播放次数和 On-The-Go 歌单的曲目位置。中断时，若旧索引仍在，恢复会把暂存音频放回原位。若新索引已经提交，恢复会继续完成本批清理。此项用于处理尚未结束的批次。

连接时，程序先读取设备上的 SysInfo。若未找到匹配的 GUID，会从当前盘符定位到物理磁盘，并沿 Windows 设备树读取 Apple USB 父设备的标识。只有通过这台 iPod 现有曲库的 Hash58 校验，界面才会显示「可写入」。仍显示只读时，可以在「填写设备 GUID」手动输入已知的 16 位十六进制 FireWire GUID。

侧栏的设备卡片会显示这台 iPod 的机型、代数和机身颜色，并配上对应外形和颜色的示意图。型号来自设备上的 SysInfo、通过 USB 读取到的序列号，或 USB 设备的产品编号。只有产品编号时能确定机型和代数，颜色显示为中性。设备上的文件与硬件报告的不一致时，以硬件为准。读取是只读操作。无法确定型号时显示中性的示意图，其余功能照常可用。

## 源码与构建

使用带 Tcl/Tk 的 Windows x64 CPython 3.12。Python 运行时、界面和曲库引擎随 EXE 分发，用户运行时无需安装 Python 或 iTunes。源码目录下执行以下命令可以运行测试和构建。程序生成在 `dist\ClassicDrop`，安装包需要 [Inno Setup 6](https://jrsoftware.org/isinfo.php)，生成在 `dist\installer`。macOS 下用 `bash build_mac.sh` 生成 `dist/ClassicDrop-macOS-<架构>-v<版本>.dmg`。

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-build.txt
.venv\Scripts\python tools\fetch_qaac.py
.venv\Scripts\python -m unittest discover -s tests -p "test_*.py" -v
.\build.ps1 -Python .\.venv\Scripts\python.exe
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" installer\ClassicDrop.iss
```

版本号只写在 `version.py`。推送与它一致的 `v*` 标签后，GitHub Actions 会运行测试、打包，并创建草稿 Release。核对附件、写好更新说明并手动发布后，已安装的程序才会收到更新提示。构建产物可以跑 `dist\ClassicDrop\ClassicDrop.exe --self-test 报告.json` 自检：校验 wasmtime、HASH58/HASHAB 签名、FFmpeg、refalac 和 tkdnd，全部通过才返回 0。

本项目使用 GPL-3.0-or-later。曲库读写、设备校验和索引处理复用 [iOpenPod](https://github.com/TheRealSavi/iOpenPod/tree/5e48bd7b6ea0903a1ffc5f7a44c02bacac5496d0) 的 iPodDB 和 device_registry，源码随附于 vendor，版权归属见 vendor/COPYING.md。音频标签使用 [Mutagen](https://github.com/quodlibet/mutagen)，文件拖放使用 [tkinterdnd2](https://github.com/Eliav2/tkinterdnd2)。测试音频为本项目生成的短正弦波。
